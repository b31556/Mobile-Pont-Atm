# Pont ATM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Pont ATM system: a Node/SQLite server with an admin website, and an Android app that reads MIFARE Classic 1K cards and credits points through the server.

**Architecture:** The server is the only owner of balances. The app sends `{cardUid, amount, idempotencyKey}` to `POST /charges`. The admin website is static HTML/JS served by the same Fastify process and calls the same JSON API. The app is split into a pure-Kotlin core (API client, state machines, UID parsing) that is unit-tested on the JVM, and thin Compose screens on top.

**Tech Stack:** Server: Node 22, TypeScript, Fastify 5, better-sqlite3, @fastify/jwt, @fastify/multipart, bcryptjs, vitest. App: Kotlin, Jetpack Compose, OkHttp, kotlinx.serialization, Coil, JUnit4. Build with JDK 21 (`JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64`; the default `java` is 11 and is too old for the Android Gradle Plugin), compileSdk 36 (installed at `~/Android/Sdk`).

**Spec:** `docs/superpowers/specs/2026-10-22-pont-atm-design.md`. Visual reference: `sketch/index.html`.

## Global Constraints

- Android only, min SDK 26. MIFARE Classic 1K identified by UID (colon-separated uppercase hex, e.g. `04:A2:3B:1C`).
- Points are whole numbers, 1 to 9999 per charge. A balance never goes below 0.
- Every charge carries an `idempotencyKey`. A repeated key returns the original result and credits nothing.
- Storno is a full reversal only, creates a reversing row (`type='storno'`, negative amount, `ref` = original id) and marks the original `stornoed`.
- Server API is JSON over HTTP. Terminal tokens and operator tokens are JWTs. Admin and operator tokens are separate roles.
- Colors from the sketch: ink `#12202B`, green `#17A34A`, amber `#F5B31F`, red `#D23B33`, bg `#EEF1F3`. Fonts: Bricolage Grotesque (display), Figtree (text). Fall back to system fonts if the app has no bundled font.
- UI copy follows the sketch: "Give 8 points", "Next customer", "Storno", "Card is blocked", "Card not registered", "No connection".
- Server port from `PORT` env (default 3000). DB path from `DB_PATH` env (default `./data/pont.db`). `JWT_SECRET` env required outside tests.

## Review Focus

- Retry of the same charge after a lost response (same key): must return the same transaction, credit once. (Task 5)
- Two near-simultaneous charges to one card: balance must equal the sum. (Task 5)
- Storno of an already stornoed transaction, of a storno row, or one that would take the balance below 0: refused with a clear error. (Task 5)
- Charge to a blocked card or unknown UID: no balance or transaction change. (Task 5)
- UID formats the phone may hand over (4, 7 or 10 bytes, lowercase hex, reversed byte order): normalized to one canonical string. (Task 9)
- A revoked terminal's token or a deactivated staff account is refused on the next request. (Tasks 2, 3)
- Phone has NFC off or no NFC: the app says so instead of waiting forever. (Task 11)
