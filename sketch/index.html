Clickable prototype. Nothing here talks to a server.

The flow, end to end

  1. Operator signs in on a terminal phone that an admin has paired to a terminal name (like “Bar 2”).
  2. Operator types an amount and presses the green button, or taps a preset. A preset skips the button and goes straight to reading.
  3. The phone waits for a card. On tap, the app reads the tag UID (and later, a secret block) and shows a progress bar.
  4. The app sends terminal, card UID, amount and a one-time idempotency key to the server.
  5. The server finds the card, checks it isn't blocked, adds the points, stores the transaction, and replies with the holder's name, photo and new balance.
  6. The phone beeps and shows the holder's photo, so the operator can check the face matches the card.
  7. Storno: the operator opens a transaction in History and confirms. The server reverses it against the card ID it already has. No card needed.

Server API (first guess)

  • POST /auth/login operator email + password, returns a token tied to the paired terminal
  • POST /charges {cardUid, amount, idempotencyKey} returns the transaction, holder and balance
  • GET /transactions?terminal=me for the History tab
  • POST /transactions/:id/storno creates a reversing row; the original is marked stornoed
  • GET/PUT /terminals/me/presets so presets follow the terminal, not one phone
  • Admin: /cards, /terminals, /staff, /transactions

The server owns the balance. The card only identifies the person, so nothing on the tag can be edited to gain points.

MIFARE Classic 1K on Android

1K means 16 sectors of 4 blocks, 64 bytes of memory each side of the keys. Android reads it through MifareClassic in android.nfc.tech.

Two ways to identify a card

  • UID only. Works on every NFC phone and needs no keys. A 4-byte UID can be cloned with cheap hardware, which is fine for low-value points.
  • UID plus a secret block. At enrolment the server writes a random token to a sector protected with a key unique to that card. The app reads it and the server checks it. This stops simple cloning.
Phone caveat. Only phones with an NXP NFC chip can authenticate to MIFARE Classic sectors. Many Samsung, Pixel and some other models can read the UID but fail at sector reads. The terminal phones need testing before you buy a batch.

My assumptions. Tell me which are wrong.

  • “Gives out points” means crediting. Every charge adds points to the card, and storno takes them back. If you also want to spend points (a deduct mode), it is one more toggle on the charge screen.
  • Online only. With no connection the app shows an error and nothing is charged. No offline queue in v1.
  • Idempotency key per charge. A retry after a dropped reply can't double-give points.
  • Storno is a full reversal of one transaction. No partial refunds. Admins can storno from the website too.
  • Balance can't go below zero. If a card has already spent the points, the storno is refused. I haven't drawn that error state yet.
  • Presets belong to the terminal, so every operator on Bar 2 sees the same chips.
  • Staff accounts. Operators sign in on the app, and admins sign in on the website. I added a small Staff tab for it.
  • Stack, my suggestion: native Kotlin with Jetpack Compose for the app, since NFC reader mode is simplest there. The server stack is open.
